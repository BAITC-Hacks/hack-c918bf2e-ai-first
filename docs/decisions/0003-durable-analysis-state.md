# 0003 — Постоянное хранение состояния анализа

## Решение

Сохраняем валидированные Pydantic-снимки `Analysis` в PostgreSQL JSONB через asyncpg.
Один снимок включает статус, этапы, находки, исходные цитаты, реестр и журнал.
Таблица `analyses` создаётся при старте, `put` атомарно обновляет снимок по ID.
Схема API не меняется; готовый результат переживает рестарт.

Почему JSONB: за оставшееся время важнее не потерять проверяемый результат,
чем вводить нормализованную схему для всех типов доказательств. Это не векторизация,
не RAG и не память модели. pgvector пока не участвует в анализе.

## Жизненный цикл

- Перед приёмом запросов подключаемся к БД и создаём таблицу.
- Отдельное соединение держит advisory lock одного backend-процесса.
  Второй процесс не запускается и не меняет чужие активные задания.
- При старте оставшиеся `queued/processing` атомарно становятся `failed` с
  `ANALYSIS_INTERRUPTED`. Завершённые результаты не изменяются.
- При штатной остановке фоновые задачи отменяются, последний этап сохраняется.
- При потере соединения с блокировкой хранилище отказывает; требуется рестарт.
  Нет незаметного переключения на память и потери результатов.
- Пул и запросы имеют таймауты; `/health` проверяет доступность хранилища.
- In-memory реализация остаётся только явной тестовой подменой с JSON-снимками.

Это одноинстансный прототип, не распределённая очередь. LLM-вызов, уже отправленный
внешнему провайдеру, нельзя гарантированно отменить при остановке. Незавершённые
анализы автоматически не перезапускаем, чтобы не повторять списание кредитов.
Авторизации и списка истории в UI пока нет; результаты доступны по ID.
Старые результаты версии с хранением только в памяти сами в БД не появляются.

## Проверка

Тесты создают уникальную временную схему в настоящей PostgreSQL и удаляют только её.
Проверяют JSON round-trip всех полей, upsert, повторный старт, recovery, сохранность
результата через перезапуск FastAPI и отказ второго владельца блокировки.

Поведение пула и таймауты: [официальная документация asyncpg](https://magicstack.github.io/asyncpg/current/api/index.html).
