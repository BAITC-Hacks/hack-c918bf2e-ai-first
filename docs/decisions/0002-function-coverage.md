# Реестр функций и охват фрагментов

Для корпоративной сверки недостаточно списка найденных отклонений: отсутствие
находки не показывает, была ли обязанность вообще рассмотрена.

## Решение

1. Парсер задаёт полный список текстовых фрагментов.
2. Извлекатель рассматривает ограниченные пакеты фрагментов. На каждый source_id
   требуется одно решение: функции, нефункциональный текст или требует проверки.
3. Код проверяет цитаты. Пропуски, неоднозначность и ошибки API сохраняются как
   needs_review, не удаляются из знаменателя охвата.
4. Отдельный сопоставитель обрабатывает ID функций небольшими пакетами; каждый пакет
   видит полный компактный реестр действий противоположной стороны. Аналитик отчёта
   не должен одновременно генерировать сотни строк реестра. Код дополняет пропущенные строки,
   проверяет принадлежность ID сторонам и противоречие «новая + сопоставленная».
5. Контролёр получает исходники и реестр. Исправление отчёта ограничено настройкой и
   сохраняет результаты пакетного сопоставления. Незакрытые записи требуют проверки.

## Обратные соответствия

Несопоставленные функции ПОСЛЕ проверяются по полному реестру ДО в пределах общего
лимита пакетов. Подтверждённое моделью отсутствие пары может дать гипотезу `added`;
найденные обратные связи сохраняются как кандидаты в `after_ids` строки ДО со
статусом `needs_review`. Они не считаются подтверждёнными сопоставлениями.

При разделении или объединении функций прежние связи не удаляются. Если прямая
сверка указала потерю, а обратная нашла соответствие, потеря заменяется явным
противоречием для проверки. Неизвестные ID, неоднозначные ответы и неверная форма
обратной связи не закрывают реестр. Уменьшение числа строк `needs_review` после
объединения кандидатов в одну строку само по себе не означает улучшения точности.

Structured Outputs задаёт форму ответа, но не гарантирует его фактическую
правильность — поэтому схема дополняется кодовыми проверками и контрольными
сценариями. См. [официальную документацию OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs).

## Чего метрики НЕ доказывают

- 100% рассмотренных фрагментов не означает 100% извлечённых обязанностей.
- Нефункциональным фрагмент может быть признан ошибочно.
- Точная цитата не гарантирует правильной трактовки действия или исполнителя.
- Реестр содержит упоминания обязанностей; повторение в разных разделах может
  дать несколько записей. Это не численность уникальных функций компании.
- Статус lost — гипотеза в пределах переданного комплекта, не кадровое решение.

В интерфейсе отдельно показаны охват фрагментов, сопоставленные функции ДО и
незакрытые записи; ни одна величина не называется точностью системы.
