# Требования кейса и критерии приёмки

Источник: техническое задание владельца задачи — Казахтелеком. Документ заказчика
не хранится в репозитории; здесь зафиксировано проверяемое изложение требований.

## Основной сценарий

Сотрудник загружает документы «до» и «после» реорганизации. Система определяет
изменения структуры, сопоставляет функции, показывает риски с доказательствами и
формирует рекомендательное заключение.

## Must have

1. Определить реорганизованные, сохранённые и созданные подразделения.
2. Сопоставить функции и обнаружить потенциальные потери.
3. Найти дублирование функций и потенциальный конфликт интересов.
4. Для каждого вывода показать документ, пункт и точную цитату.
5. Сформировать понятное аналитическое заключение.
6. Принимать DOCX, PDF и XLSX.

## Ограничения качества

- Выводы являются рекомендациями и требуют проверки ответственным сотрудником.
- Запрещены существенные выводы без подтверждения загруженными документами.
- Ссылка считается валидной, только если пункт существует, а цитата содержится в
  извлечённом тексте. Невалидный вывод автоматически исключается из результата.
- Простая перенумерация или редактура без изменения смысла не считается потерей.

Редакции №8 и №9 положения о внутреннем аудите должны как минимум показать:

- создание Департамента ИТ-аудита и анализа данных (ДИТААД), пункт 3.4;
- создание Департамента операционного аудита (ДОА), пункт 3.4;
- сохранение ДНМ и ДККМ, пункт 3.4;
- передачу делегирования контроля проверки директору операционного аудита,
  пункт 9.37;
- добавление мер по раскрытию потенциального конфликта интересов при работе с

  пункт 9.15.

Формулировки результата могут отличаться, но ссылки и смысл должны сохраняться.

## Опционально

- проверка функций по законодательству, стандартам и требованиям регуляторов;
- сравнение с открытыми структурами других операторов;
- рекомендации по перераспределению функций и устранению пересечений.

Опциональные возможности реализуются только после стабильного основного сценария.
