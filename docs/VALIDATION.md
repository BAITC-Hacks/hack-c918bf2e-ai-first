# Проверки реализации

Проверено локально 23 сентября 2026 года. Это инженерные проверки прототипа,
не сертификация качества и не экспертная разметка всех функций заказчика.

## Автоматические проверки

- Backend: 70 тестов — парсеры, цитаты, реестр фрагментов, потерянные ответы модели,
  неоднозначные ID, ограничения пакетов, сопоставления и полный путь API с заглушкой провайдера.
- Включены 4 интеграционные проверки настоящей PostgreSQL: сохранение JSON и recovery,
  повторный запуск FastAPI, запрет второго backend-процесса и отказ при потере блокировки.
  Также проверяются отмена задачи и отсутствие технических секретов в ошибках API.
- Структурные риски: проверены пары ПОСЛЕ/ПОСЛЕ и ДО/ДО, отказ при смешении редакций,
  повторе локатора, выдуманной цитате и неправильном документе; все источники входят
  в заключение, риски сохраняются в PostgreSQL. Это проверки правил, не точности модели.
- Frontend: TypeScript и production build; 41 регрессионный сценарий в 7 тестовых
  файлах: заключение, охват, фильтры реестра, источники, структурные риски и
  разделение демо/реальных файлов, включая повторный запуск с исходными файлами анализа.
  API-клиент проверен при недоступном runtime-конфиге, ответах HTML вместо JSON,
  некорректном JSON, HTTP-ошибках, сетевых сбоях и таймаутах заголовков/тела ответа.
- Для проверки реальной модели есть `backend/scripts/live_registry_smoke.py`.
  Создаёт DOCX в памяти и проверяет пять заранее заданных исходов. Кредиты расходуются
  только при явном запуске скрипта, обычный pytest не обращается к модели.
- После включения пакетного сопоставителя полный путь через работающий API прошёл
  контрольный пример за 26 секунд: 10/10 фрагментов рассмотрены, пять ожидаемых
  исходов совпали, незакрытых сопоставлений нет. Это один небольшой синтетический кейс.

## Редакции положения заказчика №8 и №9

Парсер получил 981 текстовый фрагмент. Извлекатель сформировал 556 записей функций
ДО и 520 ПОСЛЕ; 968 фрагментов имеют решение, 13 требуют проверки. Записи могут
включать повторные упоминания обязанностей — это не число уникальных функций компании.

Первый вариант единого вызова анализа дал только 13 сопоставленных функций ДО
и оставил 1049 незакрытых строк реестра. Благодаря отдельному учёту пропуски
стали видимы и не были ошибочно обозначены как потери.

После разделения анализа отчёта и пакетного сопоставления проверен новый
сопоставитель на **том же ранее извлечённом реестре**:

| Показатель | Единый вызов | Пакетный сопоставитель |
|---|---:|---:|
| Сопоставленные функции ДО | 13 / 556 | 506 / 556 |
| Незакрытые строки реестра | 1049 | 79 |

Пакетный этап занял около 85 секунд. Это время **только повторного сопоставления**,
без извлечения, аналитического отчёта и контролёра. Полный обновлённый прогон этих
документов с нуля на этом этапе ещё не измерялся; более поздний прогон приведён ниже.

Количество полученных решений — 556. Связь с ПОСЛЕ закрыта не у каждой записи:
отсутствие пары, неопределённость или неполное извлечение остаются видимыми.
Доля 506/556 не является точностью или доказанной полнотой. Корректность всех 506
связей ещё не проверена человеком. Содержимое документов и результаты с цитатами
заказчика не включены в репозиторий.

## Полный повторный прогон с PostgreSQL и живым журналом

После пакетного сопоставления и внедрения хранения выполнен полный анализ редакций
№8/№9: **451,9 секунды** от создания до последней записи результата в PostgreSQL.
На этой версии блок структурных рисков ещё не был добавлен. Результат:

- 981 фрагмент, 971 рассмотрен, 10 требуют проверки;
- 532 записи функций ДО и 546 ПОСЛЕ;
- 501 функция ДО имеет пару; 68 строк сопоставления требуют проверки;
- 16 принятых находок и 6 изменений структуры;
- оценка контролёра 0,49: остаются ошибки и пробелы, отражённые в предупреждениях.

В результате присутствуют ДИТААД/ДОА, сохранение ДНМ/ДККМ и изменения с источниками
9.37, 9.15, 4.4. Это проверка отдельных опорных примеров, не экспертиза всех выводов.
Контролёр отметил спорные связи реестра и пропуск части новой обязанности мониторинга.
Результат не должен использоваться как окончательное заключение без проверки сотрудником.

Изменение числа извлечённых записей относительно предыдущего прогона показывает
вариативность модели: это не неизменный подсчёт уникальных корпоративных функций.
Промежуточный реестр и журнал были доступны через API до окончания анализа.

Результат пережил пересоздание backend-контейнера: контрольная сумма JSONB до и после
совпала, GET по прежнему ID вернул completed с прежними находками и реестром.

## Реальная модель: структурные риски

Отдельный синтетический smoke-test прошёл за 72,2 секунды. Найдены два ожидаемых
риска с парами источников ПОСЛЕ/ПОСЛЕ: самопроверка закупок (2.1/2.2) и дублирование
отчётности (2.3/2.4). Независимый аудит другим отделом в ДО не объявлен конфликтом.
Оба риска вошли в заключение; журнал наблюдался ещё при processing.

Это успешная проверка конкретных рисков, а не всего анализа: 4 строки реестра требуют
проверки, итоговая оценка 0,49. Контролёр также предъявил претензию к неиспользуемому
модельному тексту conclusion. После этого исправлена его входная проекция: критик
теперь видит заключение, собранное кодом из проверенных находок; регрессионный тест
не допускает оценки выдуманного чернового текста вместо фактически публикуемого отчёта.
Этот последний патч отдельно проверен тестами, без повторного платного прогона.

## Интеграция нового frontend и перезапуск

- Функции подготовки данных frontend проверены на сохранённых ответах работающего
  API: 569 строк реестра заказчика и 9 строк контрольного анализа. Количество строк
  «требует проверки» совпало со счётчиками API. Оба структурных риска контрольного
  прогона вошли в копируемое заключение со всеми источниками и рекомендациями.
- `docker compose up --build -d --force-recreate --wait backend frontend` завершился
  успешно; frontend, backend и PostgreSQL имеют статус healthy.
- Все три сохранённых анализа доступны после пересоздания контейнеров; контрольные
  суммы JSONB до и после совпали. Новые платные запросы к модели не запускались.
- HTTP-проверки прошли для health, SPA-маршрутов, ресурсов сборки, runtime-конфига,
  CORS и чтения сохранённого анализа. `config.js` отдаётся с `no-store`, ресурсы —
  с `immutable`, отсутствующий ресурс возвращает 404, а не HTML приложения.

## Проверка в подключённом Chrome и исправление маршрутизации API

После подключения Chrome обнаружена ошибка реального режима: браузер блокировал
`/config.js` (`ERR_BLOCKED_BY_CLIENT`), а запросы `/api` на адресе frontend попадали
в SPA fallback и возвращали HTML вместо JSON. Конкретный источник клиентской
блокировки не установлен; настройки безопасности браузера не изменялись.

Добавлен same-origin proxy `/api/` в nginx и Vite. Теперь стандартный Docker-запуск
не зависит от доступности необязательного runtime-конфига. Внешний адрес API можно
задать явно; ошибочный ответ сервера показывается понятным сообщением, без подмены
реального результата демоданными.

После `docker compose up --build -d --no-deps --wait frontend`:

- Все 41 регрессионный сценарий frontend, TypeScript и production build прошли.
  Все три сервиса healthy; backend и PostgreSQL в этом перезапуске не пересоздавались.
- Проксированные ответы для сохранённых анализов заказчика и структурных рисков
  совпали с прямыми ответами backend. Неизвестный API-маршрут вернул JSON с HTTP 404.
- Multipart-запрос размером более 2 МБ прошёл nginx до валидации FastAPI (HTTP 422
  из-за намеренно отсутствующего комплекта ПОСЛЕ). Новый анализ не создавался.
- В Chrome открылся реальный сохранённый результат редакций №8/№9. Проверены
  отображение неполного охвата, переход к 68 требующим проверки строкам из 569
  и раскрытие цитаты с документом и номером пункта.
- В сохранённом синтетическом анализе с ответами реальной модели проверены обе
  карточки структурных рисков, источники ПОСЛЕ/ПОСЛЕ, карточка отклонения ДО/ПОСЛЕ
  и итоговое заключение с цитатами всех рисков.

Это браузерная проверка чтения и взаимодействия с сохранёнными результатами,
не новый сквозной прогон загрузка → LLM → результат. Новые платные обращения к
модели не выполнялись. Мобильная вёрстка, печать/PDF и фактическое содержимое
системного буфера обмена в этой проверке не подтверждены.
