# Frontend: дизайн

Источник истины — дизайн-пакет «Сверка · AI First»:
[`../Дизайн-пакет Сверка AI First/handoff/HANDOFF.md`](../Дизайн-пакет%20Сверка%20AI%20First/handoff/HANDOFF.md)

`Сверка - 2 Прототип.dc.html`.

## Расхождения handoff и API-контракта

Данные берутся строго по [`docs/API_CONTRACT.md`](../../docs/API_CONTRACT.md) и Pydantic-схемам
backend. Handoff §10 описывает более богатую модель; UI адаптирован так:

| Handoff §10 | Контракт | Как сделано |
|---|---|---|
| `status: running / partial` | `processing`, без `partial` | `processing` = выполнение; баннер «Частичный результат» не реализован |
| `summary.functions_before`, `duplicate`, `duration_sec` | `before_functions`, `duplicates`, нет длительности | «Время выполнения» показывается, только если вкладка наблюдала прогон до конца |
| `organization_changes[].before/after` — строки, одна `evidence` | `before_name/after_name`, `before/after` evidence | Цитата-основание: `after ?? before` |
| `conclusion` — объект из 5 секций | строка | 01 «Резюме» — текст backend; 02–05 собираются на клиенте из `findings` и `summary` (`src/utils/conclusion.ts`). Секция 04 строится по выводам `duplicate` и подписана об этом |
| `warnings[] = {code, message}` | `string[]` | QC-блок — предупреждения с фразой «контроль качества» (так пишет backend) |
| `error.document`, «Продолжить без документа» | нет | Не реализовано; «Повторить запуск» повторно отправляет файлы из формы |
| Короткие id `F-01` | backend отдаёт UUID | На клиенте показывается `F-NN` по приоритетной сортировке, если id не в формате `F-NN` |
| Кол-во документов в шапке результата | нет | Показывается только для анализов, запущенных в этой вкладке |

## Журнал агентов (`agent_trace`, `quality_score`)

Компонент `AgentTrace` показывается на экране выполнения (под этапами) и в обзоре результата
(после сводки). Из записи используются только `agent`, `action`, `status` и `summary`;
длинные summary обрезаются до 600 символов. Промпты и промежуточные рассуждения не
выводятся — в контракте их нет, а лишние поля игнорируются (`src/utils/trace.ts`).

| action | Подпись |
|---|---|
| `plan` | План анализа |
| `extract` | Извлечение документов |
| `compare` | Первичный анализ |
| `evaluate` / `re-evaluate` | Оценка критика / Повторная оценка критика |
| `revise` | Исправление по замечаниям |
| `accept_revision` / `rollback` | Исправление принято / Откат к лучшей версии |
| `verify` | Проверка доказательств |

Неизвестные `agent`/`action` выводятся как есть. Бейдж итога самокоррекции:
«Исправления не потребовались» · «Исправление принято» · «Откат к лучшей версии» ·
«Выполнено исправление» (revise без решения оркестратора). `quality_score` — «Оценка
критика N%» в шапке результата, в журнале и в блоке «Контроль качества» заключения.

Записи рендерятся по мере появления в ответе. Текущий backend заполняет `agent_trace`
только после завершения анализа, поэтому на реальном прогоне журнал виден в результате;
demo-mock раскрывает шаги постепенно.

## Реализовано из P1

Тёмная тема, word-diff в цитатах, ↑/↓/Esc и `?finding=` в URL, раскрытие цитаты в карте,
«Отметить как проверенное» (localStorage), сортировки по уверенности и подразделению, QSkeleton,
mobile-карточки и полноэкранная панель, `prefers-reduced-motion`.

## Честность интерфейса (демонстрация для Казахтелекома)

- **Демо и реальный анализ не смешиваются.** Форма `/new` находится в одном режиме
  (`draft.mode`). Добавление настоящего файла убирает демозаглушки; переход к демо при
  загруженных документах требует подтверждения. Ошибки API никогда не заменяются
  демонстрационным результатом. Демо помечено «Демонстрация интерфейса — заранее
  подготовленные данные, анализ документов не выполняется» на всех экранах, в
  заключении, в копируемом тексте и при печати.
- **Передача данных.** До загрузки сообщается, что текст документов уходит во внешний
  API OpenAI; утверждений о внутреннем контуре и конфиденциальности нет. Потенциальные
  конфликты интересов показываются отдельным блоком `structural_risks` с источниками;
  это гипотезы модели для проверки специалистом, не экспертное заключение.
- **Доказательства.** `before` всегда «ДО», `after` — «ПОСЛЕ» (и для `duplicate`).
  При отсутствии цитаты: «Подтверждённый фрагмент не представлен»; при неполном охвате
  панель показывает ограничение. Страница выводится только если её передал сервис.
- **Завершение ≠ качество.** Шапка — «Обработка завершена» + чип охвата; блок «Охват
  обработки» на обзоре и «Ограничения результата» в заключении показывают
  `unresolved_fragments` и `needs_review_mappings`. Охват — не точность, оценка
  критика — не измеренная точность. Шкала выполнения показывает этап, не ETA.
- **Восстановление.** 404, недоступный сервис/503, `failed`, `ANALYSIS_INTERRUPTED`,
  отсутствие реестра и пустой результат имеют отдельные состояния. «Повторить запуск»
  отправляет только файлы этого запуска (`retryPlan`); после обновления страницы или
  по ссылке — просьба загрузить документы заново. «Отметить в этом браузере» —
  локальная заметка, не согласование.

Регрессионные тесты: `npm test` (`tests/*.test.mjs`).

## Потенциальные риски внутри редакции (`structural_risks`)

По `docs/FRONTEND_RISKS_HANDOFF.md`. Отдельный блок на обзоре (`StructuralRisks.vue`) и
раздел 04 заключения; `Finding.before/after` не меняются.

- Виды: «Дублирование функций» и «Потенциальный конфликт интересов» — не смешиваются,
  duplicate не превращается в conflict_interest.
- Сторона каждой цитаты берётся из `evidence[i].side`: две ссылки ПОСЛЕ — нормальный
  случай. Word-diff между разными подразделениями не строится.
- `null`/нет поля — «блок не передан»; `[]` — «в принятых результатах не указаны; это не
  доказывает отсутствие». Рядом остаются предупреждения об охвате.
- Сводка и фильтры таблицы считают только `findings`; у блока рисков свои счётчики по
  виду и важности. Для результатов нового формата пустая ячейка «Дублирование» в сводке
  скрыта, вместо неё — ссылка на блок рисков.
- Копируемое/печатное заключение содержит каждый риск, все ссылки, цитаты и
  рекомендации; рекомендации high/medium добавляются в раздел 05.
- Демо-набор переведён на новый формат: дублирования — в `structural_risks`
  (ПОСЛЕ + ПОСЛЕ), плюс один пример конфликта интересов.
