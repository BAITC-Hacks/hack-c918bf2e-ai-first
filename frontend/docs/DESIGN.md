## Расхождения handoff и API-контракта

Данные берутся строго по [`docs/API_CONTRACT.md`](../../docs/API_CONTRACT.md) и Pydantic-схемам
backend. Handoff §10 описывает более богатую модель; UI адаптирован так:

| Handoff §10 | Контракт | Как сделано |
|---|---|---|
| `status: running / partial` | `processing`, без `partial` | `processing` = выполнение; баннер «Частичный результат» не реализован |
| `summary.functions_before`, `duplicate`, `duration_sec` | `before_functions`, `duplicates`, нет длительности | «Время выполнения» показывается, только если вкладка наблюдала прогон до конца |
| `organization_changes[].before/after` — строки, одна `evidence` | `before_name/after_name`, `before/after` evidence | Цитата-основание: `after ?? before` |
| `conclusion` — объект из 5 секций | строка | 01 «Резюме» — текст backend; 02–05 собираются на клиенте из `findings` и `summary` (`src/utils/conclusion.ts`). Секция 04 строится по выводам `duplicate` и подписана об этом |
| `warnings[] = {code, message}` | `string[]` | QC-блок — предупреждения с фразой «контроль качества» (так пишет backend) |
| `error.document`, «Продолжить без документа» | нет | Не реализовано; «Повторить запуск» повторно отправляет файлы из формы |
| Короткие id `F-01` | backend отдаёт UUID | На клиенте показывается `F-NN` по приоритетной сортировке, если id не в формате `F-NN` |
| Кол-во документов в шапке результата | нет | Показывается только для анализов, запущенных в этой вкладке |

## Журнал агентов (`agent_trace`, `quality_score`)

Компонент `AgentTrace` показывается на экране выполнения (под этапами) и в обзоре результата
(после сводки). Из записи используются только `agent`, `action`, `status` и `summary`;
длинные summary обрезаются до 600 символов. Промпты и промежуточные рассуждения не
выводятся — в контракте их нет, а лишние поля игнорируются (`src/utils/trace.ts`).

| action | Подпись |
|---|---|
| `plan` | План анализа |
| `extract` | Извлечение документов |
| `compare` | Первичный анализ |
| `evaluate` / `re-evaluate` | Оценка критика / Повторная оценка критика |
| `revise` | Исправление по замечаниям |
| `accept_revision` / `rollback` | Исправление принято / Откат к лучшей версии |
| `verify` | Проверка доказательств |

Неизвестные `agent`/`action` выводятся как есть. Бейдж итога самокоррекции:
«Исправления не потребовались» · «Исправление принято» · «Откат к лучшей версии» ·
«Выполнено исправление» (revise без решения оркестратора). `quality_score` — «Оценка
критика N%» в шапке результата, в журнале и в блоке «Контроль качества» заключения.

Записи рендерятся по мере появления в ответе. Текущий backend заполняет `agent_trace`
только после завершения анализа, поэтому на реальном прогоне журнал виден в результате;
demo-mock раскрывает шаги постепенно.

## Реализовано из P1

Тёмная тема, word-diff в цитатах, ↑/↓/Esc и `?finding=` в URL, раскрытие цитаты в карте,
«Отметить как проверенное» (localStorage), сортировки по уверенности и подразделению, QSkeleton,
mobile-карточки и полноэкранная панель, `prefers-reduced-motion`.
