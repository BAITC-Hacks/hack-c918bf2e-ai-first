# Frontend: главный demo flow

Enterprise/B2B интерфейс аудита реорганизации. Не чат: пользователь загружает
два комплекта документов, наблюдает работу агента и получает проверяемый отчёт.
Источник данных — `docs/API_CONTRACT.md` (без изменений контракта).

## Маршруты

| Маршрут | Экран | Данные |
|---|---|---|
| `/` | Загрузка комплектов | `POST /api/v1/analyses` |
| `/analyses/:id` | Выполнение → результат | polling `GET /api/v1/analyses/{id}` каждые 1,5 с |

`id` с префиксом `demo-` обслуживается локальным mock того же JSON-формата
(`src/api/mock.ts`), пока backend недоступен.

## 1. Загрузка

```text
┌ AI First · Аудит оргструктуры ─────────────────────────────── [Демо-пример] ┐
│ Новый анализ реорганизации                                                  │
│ Название анализа [Реорганизация блока эксплуатации_________________]        │
│ ┌ Комплект «до» ──────────────┐   ┌ Комплект «после» ───────────┐           │
│ │  ⇪ Перетащите PDF/DOCX      │   │  ⇪ Перетащите PDF/DOCX      │           │
│ │  Положение_до.pdf  1,2 МБ ✕ │   │  Положение_после.docx 0,8 ✕ │           │
│ └─────────────────────────────┘   └─────────────────────────────┘           │
│ Что проверит агент: потери · дубли · перемещения · изменения · добавления   │
│                                            [Открыть демо] [Запустить анализ]│
└─────────────────────────────────────────────────────────────────────────────┘
```
Кнопка запуска активна при ≥1 файле в каждом комплекте. Недопустимые форматы
отклоняются с уведомлением. Ошибка сети → уведомление с действием «Запустить на
демо-данных».

## 2. Выполнение (status = queued | processing)

```text
│ Реорганизация блока эксплуатации             Выполняется · 00:07            │
│ ████████████░░░░░░░░░░ 48%   Текущий шаг: Сопоставление                     │
│ ✓ 1 Извлечение документов                                                   │
│ ✓ 2 Выделение функций                                                       │
│ ◌ 3 Сопоставление            ← активный, спиннер                            │
│ ○ 4 Проверка доказательств                                                  │
│ ○ 5 Формирование заключения                                                 │
```
`failed` → красный баннер `error.code` + `error.message`, шаг с ошибкой отмечен,
действия «Повторить опрос» и «Новый анализ». Сетевые сбои опроса: до 3 повторов,
затем recoverable-ошибка.

## 3–6. Результат (status = completed)

```text
│ Реорганизация…  ✓ Завершено · 5/5 шагов           [Копировать] [Печать]     │
│ ┌До 42┐┌После 44┐┌Потеряно 3┐┌Добавлено 5┐┌Перемещено 2┐┌Изменено 4┐┌Дубли 2┐┌Высокий риск 3┐
│  (клик по KPI фильтрует таблицу)                                            │
│ ┌ Отклонения ─────────────────────────────┐ ┌ Детали ─────────────────────┐ │
│ │ [Потеря 3][Добавл 5]… [Риск ▾] [Поиск ] │ │ ● Высокий  Потеря  94%      │ │
│ │ Риск  Тип     Функция      Подразд.  Ув.│ │ Утрата функции контроля…    │ │
│ │ ●Выс  Потеря  Контроль ав… ДЭ → —   94% │ │ Пояснение                   │ │
│ │ ●Сред Перем.  Учёт ВОЛС    ДЭ → ДИ  88% │ │ ┌ До ─────────┐┌ После ─────┐│ │
│ │ …                                       │ │ │п.3.2.4 стр.7││ не найдено ││ │
│ └─────────────────────────────────────────┘ │ │«Осуществляет…»└───────────┘│ │
│                                             │ Рекомендация ▸ Назначить…   │ │
│                                             └─────────────────────────────┘ │
│ ┌ Итоговое заключение ─────────────────────────────────────────────────────┐│
│ │ текст conclusion · warnings                                              ││
```
- Таблица по умолчанию скрывает `unchanged` (переключатель), сортировка: риск,
  затем уверенность.
- Уверенность: ≥85 % высокая, 60–85 % средняя, <60 % «требует проверки экспертом».
- `before`/`after` = `null` → явное пустое состояние («Функция отсутствует в
  комплекте „после“»).
- < 1024 px: панель деталей открывается диалогом; KPI в 2–4 колонки.

## Визуальный язык

Тёмно-синяя шапка, светлый серый фон, белые карточки с тонкой рамкой, без
теней-«пузырей». Цвет несёт смысл только для риска и типа изменения:
потеря — красный, дубль — фиолетовый, изменение — янтарный, перемещение — синий,
добавление — зелёный, без изменений — серый.
